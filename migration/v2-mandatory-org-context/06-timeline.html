Migration guide · Chapter 06

Timeline & deprecation

One date matters: March 2027. This chapter says what happens before it, what happens on it, and how to be sure you are ready.

The headline

The eight replaced endpoints are deprecated today and are removed in March 2027. After that date they return an error instead of data. There is no extension and no opt-out.

01The timeline

  • Now — the replacements are live

    Both the old and the new endpoints answer

    The three organization-scoped listings are available and documented. The eight deprecated endpoints still respond, so nothing of yours has broken. This is the window in which you migrate at your own pace.

  • Now — documentation

    The old endpoints are out of the v2 reference

    They are removed from the API reference, the OpenAPI specifications, the OKF knowledge bundle, the Postman collection and all seven SDKs. A new developer reading the docs today will not find them, and an upgraded SDK will not compile against them.

  • Throughout the window

    Deprecated means unsupported, not merely old

    The deprecated endpoints receive no fixes, no new fields and no behaviour changes. A bug found in one of them will be closed with "migrate to the organization-scoped replacement". Treat anything still calling them as already broken, just not yet failing.

  • March 2027 — removal

    The eight endpoints stop answering

    Requests to the deprecated paths no longer return data. Any integration still calling them fails at that point. There is no silent fallback to the new endpoints — the URLs and the response shapes are different, so a redirect would break callers just as surely.

03What "deprecated" means in practice

People read "deprecated" as "still fine for now". It is more specific than that:

QuestionAnswer
Does it still return correct data today?Yes.
Will it get bug fixes?No.
Will it get new fields when the new endpoints do?No. They will drift apart.
Will it appear in the documentation?No. It is already removed from the reference.
Will the SDKs still expose it?No. The methods are gone from all seven SDKs today.
Is there a warning header on the response?Do not rely on one. Build your own monitoring — see section 5.
Will the date move?Plan as though it will not.
The SDKs are ahead of the server

The methods were removed from the SDKs now, while the endpoints answer until March 2027. So if you upgrade the SDK your code stops compiling before anything stops working. That is deliberate: it makes the migration a build-time problem rather than a 2027 incident.

04A sensible schedule

You have a long window. Use a short slice of it, early, rather than a panicked slice late.

  1. Week 1 — find out how exposed you are

    Grep the code. Add the monitoring alert from chapter 05. You cannot plan until you know how many call sites exist and who owns them.

  2. Week 2 — configure the Organization ID

    Read it from Settings → Organisation, add it to configuration, and wire ZANALYTICS-ORGID into the shared request builder. One edit, most of the surface fixed.

  3. Weeks 3–4 — migrate the listings

    Work down chapter 03. Do the two changed endpoints first — they need only a header. Then the listings, where response shapes change.

  4. Week 5 — refresh the contracts

    OpenAPI, Postman, the OKF bundle, MCP tool definitions, the wiki. See chapter 05. Skipping this is how the old endpoints creep back in six months later.

  5. Then — watch the alert

    Let it stay silent across a full billing cycle, month-end and quarter-end included. Close the ticket when it has.

Why not wait until 2026?

Because the expensive part is not the code, it is the discovery: the scheduled job nobody owns, the Deluge script in a Creator app, the notebook on an analyst's laptop. Those surface slowly. Start the monitoring now and let them surface while there is still time to fix them calmly.

05Prove you are ready

Three checks. All three must pass.

Check 1 — the code is clean

grep -rnE '/restapi/v2/(orgs|workspaces|dashboards)"?$|/restapi/v2/(workspaces|dashboards)/(owned|shared)|/restapi/v2/recentviews' . \
  --include='*.java' --include='*.py' --include='*.cs' --include='*.go' \
  --include='*.php' --include='*.js' --include='*.ts' --include='*.rb' \
  --include='*.dg' --include='*.json' --include='*.yaml' --include='*.yml'

No output is a pass. Remember that a hit on /restapi/v2/workspaces is only a problem if the method is GET.

Check 2 — the traffic is zero

Your monitoring alert on the eight deprecated paths has not fired for a full billing cycle.

Check 3 — the contracts are fresh

# Your ingested OKF bundle should report 2.0.0
grep '"version"' /path/to/okf/manifest.json | head -1

# And none of the removed endpoints should appear anywhere in your copies
grep -rl "recentviews\|dashboards/owned\|dashboards/shared\|workspaces/owned\|workspaces/shared" \
  /path/to/openapi /path/to/postman /path/to/okf

No output from the second command is a pass.

06If you are reading this after March 2027

If an integration has already broken, the fastest fix is the smallest one:

  1. Find the failing call. The error will be an explicit failure on one of the eight paths listed in section 2.
  2. Get the Organization ID from Settings → Organisation.
  3. Add the ZANALYTICS-ORGID header.
  4. Change the URL per the endpoint index.
  5. Fix the response parsing — this is the step people miss. ownedWorkspaces + sharedWorkspaces became workspaces; ownedViews + sharedViews became views plus pageDetails.
  6. For dashboards, add the paging loop. Without it you will silently get only the first 100.

Chapter 03 has the full before-and-after for each one.

# Zoho Analytics v2 — mandatory organization context

Zoho Analytics REST API v2 now requires every call to name the organization it
applies to. Eight cross-organization endpoints were replaced by three
organization-scoped ones; two more kept their URL but now require a header.

**The eight removed endpoints stop answering in March 2027.** They still respond
today, so nothing is broken yet — this is the migration window.

## The facts every part of this migration depends on

1. **`ZANALYTICS-ORGID` is mandatory on every endpoint**, not just the ones below.
   Add it in your shared HTTP client or request builder once, not per call site.
2. **The Organization ID comes from configuration, not from an API call.** Read it
   once from the Zoho Analytics UI → **Settings → Organisation** and store it next
   to your client ID and refresh token. `GET /restapi/v2/orgs` was the discovery
   call and has no replacement.
3. **`8083` means the header is missing. `8084` means the ID is unknown.** Neither
   is retryable — a retry of the identical request will fail identically.
4. **`GET /restapi/v2/orgs/dashboards` is paged**, where its predecessors were not.
   Loop on `pageDetails.hasNextPage`, never on page length.

## Working rules

- **Never suggest a deprecated endpoint or method**, even as an interim step.
  There is no fallback and no redirect; the URLs and response shapes differ.
- **Check the HTTP verb before rewriting a `/restapi/v2/workspaces` path.**
  `POST` on that path is Create Workspace and is completely unaffected. A
  path-only search and replace will break it.
- **Re-pointing a dashboard URL is not enough.** The replacement is paged and
  returns an object where the old one returned an array. Both have to change.
- **Do not estimate counts or dates.** The deadline is March 2027; the counts are
  in `migration-map.json`.

# Endpoint migration — direct HTTP calls

For code that builds Zoho Analytics requests itself: curl, fetch, `requests`,
an API gateway, a Deluge `invokeurl`. If the user calls through an official SDK,
use `zoho-analytics-v2-sdk-migration` instead.

Exact paths, CONFIG parameters, field mappings and error codes are in
`../../migration-map.json`. Read values from there rather than recalling them.
Full prose with request/response examples: `../../../03-endpoint-migration.md`.

## The mapping

| Old | New |
|---|---|
| `GET /restapi/v2/orgs` | **No endpoint.** Org ID comes from configuration |
| `GET /restapi/v2/workspaces` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/workspaces/owned` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/workspaces/shared` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/dashboards` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/dashboards/owned` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/dashboards/shared` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/recentviews` | `GET /restapi/v2/orgs/recentitems` |

Unchanged URL, header now mandatory: `GET /restapi/v2/workspaces/{workspace-id}`
and `GET /restapi/v2/views/{view-id}`.

**Unaffected: `POST /restapi/v2/workspaces`** (Create Workspace). It shares a path
with a removed `GET`. Always check the verb before you rewrite that path.

## Order of work

1. **Put the Organization ID in configuration.** `ZOHO_ANALYTICS_ORG_ID`, next to
   the client ID and refresh token. Source: UI → **Settings → Organisation**.
2. **Add `ZANALYTICS-ORGID` in the shared request builder**, once. Every endpoint
   needs it now, so a per-call-site change is the wrong shape.
3. **Rewrite the paths** from the table above.
4. **Fix the response parsing** — this is where the real work is, below.
5. **Handle `8083` and `8084`** wherever the header is now required.

## Response parsing — the part that is not a URL change

**Workspaces.** `data.ownedWorkspaces[]` and `data.sharedWorkspaces[]` merge into a
single `data.workspaces[]`. Per-item fields are unchanged. If the UI genuinely
needs the two buckets, derive them client-side by comparing `createdBy` to the
caller — but check whether the split is still wanted: within one organization an
admin sees everything, and for everyone else "shared with me" *is* the whole list.

**Dashboards.** `data.ownedViews[]` and `data.sharedViews[]` merge into
`data.views[]`, and a new `data.pageDetails` appears. This endpoint is **paged**:

```python
dashboards, page = [], 1
while True:
    r = get("/restapi/v2/orgs/dashboards", config={"pageNo": page, "recordsPerPage": 100})
    dashboards.extend(r["data"]["views"])
    if not r["data"]["pageDetails"]["hasNextPage"]:
        break
    page += 1
```

> **Loop on `hasNextPage`, never on page length.** It is computed after duplicates
> and role-restricted entries are removed, so a page can hold 3 entries when you
> asked for 100 and still have more pages behind it.

**Recent items.** Response shape is unchanged — but the list is capped at 20,
scoped to the named organization, and access is checked at workspace level only,
so an entry can point at a view the caller cannot open. Names come from the
stored history record and may be stale. It costs **1 API unit**, ten times the
other two org-level listings; budget for it if you poll.

## The 100-workspace cap

Omitting `workspaceIds` fails with `7476` when the caller can see more than 100
workspaces. Fix by naming the workspaces in batches of at most 100, taken from
`GET /restapi/v2/orgs/workspaces` for the same organization, and paging within
each batch.

`workspaceIds` is **validated, not filtered** — one ID from another organization
fails the whole request with `7387`, it is not silently skipped.

## CONFIG on the dashboard listing

Stringified JSON, URL-encoded, in the `CONFIG` query parameter. Four keys only;
anything else is `8542`. `workspaceIds` (≤1,000 entries, ≤10,000 chars),
`pageNo` (1–1,000), `recordsPerPage` (1–500), `searchKey` (≤100 chars). Limits and
the error code for each are in `migration-map.json` under `config_parameters`.

## Errors to handle

| Code | Means | Do |
|---|---|---|
| `8083` | Header missing or empty | Send it. Never retry unchanged |
| `8084` | No organization with that ID | Re-read from Settings → Organisation |
| `7301` | Caller is not an active user of that organization | Use an org they belong to |
| `7103` / `7104` | Workspace / view not found **in this organization** | Check the header before the ID |
| `7476` | More than 100 workspaces in scope | Batch `workspaceIds` |
| `7387` | A `workspaceIds` entry is not in this organization | Build batches from Get Org Workspaces |
| `7430` / `7431` | Org-level listing switched off for the organization | Use workspace-level APIs, or contact support |

Full table including the eight CONFIG validation codes: `migration-map.json`
under `error_codes`, or `../../../07-troubleshooting.md`.

## Behaviour that is correct but looks like a bug

- **Empty list, HTTP 200.** Valid — nothing is visible to this caller. An
  Organization Admin or ordinary user whose primary email is unverified gets an
  empty list; the Account Admin does not.
- **`isDefault` on a workspace** means the *caller's* default, not the
  organization's.
- **`folderId` is the string `"null"`** when a dashboard is in no folder.
- **`createdBy` is `""`** when the caller is not an active user of the owning org.

# SDK migration — all seven languages

All seven official SDKs changed the same way. Understand the shape once and the
code is mechanical in every language.

Exact per-language before/after code is in `../../../04-sdk-migration.md`.
The method map as data, including snake_case variants, is in
`../../migration-map.json` under `sdk`.

## The shape of the change

`AnalyticsClient` now holds **only configuration and its four factories**. It has
no organization, which is exactly why the cross-organization methods used to live
on it — and why they cannot stay now that every endpoint needs one.

```
AnalyticsClient
 ├─ OrgAPI         getOrgInstance(orgId)
 ├─ WorkspaceAPI   getWorkspaceInstance(orgId, workspaceId)
 ├─ ViewAPI        getViewInstance(orgId, workspaceId, viewId)
 └─ BulkAPI        getBulkInstance(orgId, workspaceId)
```

Each instance holds the IDs you gave it and sends `ZANALYTICS-ORGID` on every
request automatically. **Get an `OrgAPI` first, then call the method on it.**
That is the whole migration.

## The method map

`ORG` = an `OrgAPI` instance, `WS` = a `WorkspaceAPI` instance. All ten were on
`AnalyticsClient` before.

| Old | New | Returns |
|---|---|---|
| `getOrgs()` | **No replacement** — read the ID from Settings → Organisation | — |
| `getWorkspaces()` | `ORG.getOrgWorkspaces()` | list |
| `getOwnedWorkspaces()` | `ORG.getOrgWorkspaces()` | list |
| `getSharedWorkspaces()` | `ORG.getOrgWorkspaces()` | list |
| `getDashboards()` | `ORG.getOrgDashboards(config)` | **object**: `views` + `pageDetails` |
| `getOwnedDashboards()` | `ORG.getOrgDashboards(config)` | **object** |
| `getSharedDashboards()` | `ORG.getOrgDashboards(config)` | **object** |
| `getRecentViews()` | `ORG.getOrgRecentItems()` | list |
| `getWorkspaceDetails(workspaceId)` | `WS.getWorkspaceDetails(config)` | workspace object |
| `getViewDetails(viewId, config)` | `ORG.getViewDetails(viewId, config)` | view object |

Naming follows each language: camelCase in Java, C#, Go, PHP and Node.js;
`snake_case` in Python and Ruby (`get_org_workspaces`, `get_org_recent_items`).

**`getWorkspaceDetails` drops its argument** — the `WorkspaceAPI` instance already
holds the workspace ID. The new `config` argument is optional (`withUserRoleInfo`);
pass `null` / `{}` / `None` if unused.

**`getViewDetails` keeps its signature** — only the object changes. It lives on
`OrgAPI` rather than `ViewAPI` because the endpoint resolves a view from the
organization alone; there is no workspace in its URL.

## Translating a build error

| Language | Message | Fix |
|---|---|---|
| Java | `cannot find symbol: method getWorkspaces()` | `ac.getOrgInstance(orgId).getOrgWorkspaces()` |
| C# | `'IAnalyticsClient' does not contain a definition for 'GetDashboards'` | `ac.GetOrgInstance(orgId).GetOrgDashboards(config)` |
| Go | `ac.GetRecentViews undefined` | `ZAnalytics.GetOrgInstance(&ac, orgId).GetOrgRecentItems()` |
| Python | `AttributeError: 'AnalyticsClient' object has no attribute 'get_workspaces'` | `ac.get_org_instance(org_id).get_org_workspaces()` |
| Ruby | `NoMethodError: undefined method 'get_orgs'` | No replacement — read the ID from the UI |
| PHP | `Call to undefined method AnalyticsClient::getDashboards()` | `$ac->getOrgInstance($org_id)->getOrgDashboards($config)` |
| Node.js | `TypeError: ac.getRecentViews is not a function` | `ac.getOrgInstance(orgId).getOrgRecentItems()` |

Upgrading the SDK and letting the build fail is the fastest way to find every
call site in Java, C# and Go.

## The trap the compiler cannot catch

`getOrgDashboards` returns an **object** with `views` and `pageDetails`. The old
`getDashboards` / `getOwnedDashboards` returned an **array**.

In **Python, Ruby, PHP, Node.js and Go this is a runtime shape change, not a
compile error.** Search for every place the old return value was iterated
directly and add `["views"]`. When migrating one of these languages, do this
pass explicitly — the build will not help you.

The listing is also paged. Always loop on `pageDetails.hasNextPage`:

```python
def all_dashboards(org, **config):
    page = 1
    while True:
        result = org.get_org_dashboards({**config, "pageNo": page})
        yield from result["views"]
        if not result["pageDetails"]["hasNextPage"]:
            return
        page += 1
```

Never loop on `len(views) < recordsPerPage` — `hasNextPage` is computed after
duplicates and role-restricted entries are removed, so short pages are normal.

## C# specific

`IAnalyticsClient` no longer declares the ten removed methods; `IOrgAPI` gained
four and `IWorkspaceAPI` gained one. **If tests mock `IAnalyticsClient`, those
mocks need updating** — the compiler will point at each one.

## Where the Organization ID belongs

Every call needs it, so put it with the other connection settings rather than
threading it through the call stack:

```python
# config.py
ORG_ID = os.environ["ZOHO_ANALYTICS_ORG_ID"]   # Settings → Organisation

# analytics.py
def org():
    return _client.get_org_instance(config.ORG_ID)

def workspace(workspace_id):
    return _client.get_workspace_instance(config.ORG_ID, workspace_id)
```

## Serving several organizations

The pattern changes from *discover then fan out* to *configure then fan out*.
Hold a list of organization IDs in configuration and create one `OrgAPI` per
organization. If the product must cover organizations you cannot know in advance,
add an "Add organization" step to the setup flow and ask the user for the ID —
the same way you already ask for a client ID and refresh token. Do not guess IDs.

# Artefact migration — specs, collections, indexes, agents

Code is only half the job. A stale contract does not fail loudly: it quietly
generates a client, autocompletes a request, or answers a developer's question
with an endpoint that stops answering in March 2027.

Per-artefact detail: `../../../05-knowledge-bases.md`. The artefact list as data,
including locations and counts: `../../migration-map.json` under `artifacts`.

## The rule that governs almost all of this

**Replace, do not merge.** Operations were *removed*. Every merge-style update —
Postman's collection merge, an incremental vector re-index, patching your old
spec copy — keeps the deleted entries and leaves the old endpoints discoverable.
Re-import or rebuild from scratch in each case.

## OpenAPI specifications

Source: `v2.0/oas/`. Read by Swagger UI, Redoc, client generators, MCP servers.

Eight operations deleted along with their response schemas; a new
`Org Level Listings` tag in `org-management-grouped-api.json` with
`getOrgWorkspaces`, `getOrgDashboards`, `getOrgRecentItems`. The
`org-id-optional` parameter is gone — every `ZANALYTICS-ORGID` is now
`"required": true`.

1. Pull the current specs whole. Do not patch the old copy.
2. Regenerate everything downstream: typed clients, request validators, gateway
   definitions, mock servers, contract tests.
3. Confirm the generated client compiles — removed operations become removed
   methods.

> Typed clients (TypeScript, Java) fail to compile, which is what you want.
> **Dynamic-language clients do not.** A Python or Ruby wrapper will keep a
> hand-written method pointing at a dead path. Grep the wrapper too.

## OKF knowledge bundle

Source: `v2.0/okf/`. Read by AI assistants, RAG indexes, `llms.txt` consumers.
Version `1.7.0` → **`2.0.0`**; 210 → **205** endpoint documents; 39 → **40** groups.

1. Re-ingest the whole bundle. Replace it — the major version bump is the signal.
2. **Drop the vector index and rebuild it from scratch.** This matters more than
   it sounds.
3. Confirm `okf/manifest.json` reports `"version": "2.0.0"` after ingestion.

```bash
# Prove the old endpoints are gone from the ingested copy — no output is correct
grep -rl "restapi/v2/recentviews\|dashboards/owned\|workspaces/owned" /path/to/okf/copy
```

> An incremental re-index adds the three new documents and leaves the eight
> deleted ones in place. A retrieval query for "list workspaces" then surfaces a
> dead endpoint **with high confidence**, because the old document is well
> written and matches well. Users trust it, write the code, and ship an
> integration that breaks in March 2027. RAG indexes are the worst offender in
> this entire migration.

## Postman

Source: `v2.0/postman/`. 210 → **205** requests. New folder
**🏢 Organization Management › Org-Level Listings** with three requests.

1. Import as a **new version**. Postman's merge keeps deleted requests.
2. Re-import the environment file too.
3. Set `organization-id` by hand from **Settings → Organisation** — the old
   bootstrap step (*run Get Org List, copy `orgId`*) no longer exists.
4. Delete the old fork, or rename it `DEPRECATED — do not use`. Someone on the
   team has it starred.
5. If it runs in CI, re-record expected responses — the dashboard listing now
   returns `pageDetails`, which the assertions have never seen.

## SDK reference documentation

Source: `v2.0/sdk/<lang>/docs/`, generated from doc comments in `<lang>/source/`.
`reference/analytics-client.md` lost ten methods, `reference/org-api.md` gained
four, `reference/workspace-api.md` gained one, and the first-call example on
every getting-started page now creates an `OrgAPI` first.

Re-publish from source if you mirror these internally. If you ship a wrapper
library, update its README with the same before-and-after — your users read your
docs, not Zoho's.

## MCP servers and AI agents

Tool definitions are a contract like any other.

| Check | Action |
|---|---|
| Tool list | Remove tools backed by the eight removed endpoints. Add three: org workspaces, org dashboards, org recent items |
| Tool schemas | `ZANALYTICS-ORGID` must be a **required** input on every tool, not optional |
| Org selection | Decide once: pin the server to one organization at start-up, or make `orgId` required on every tool. **Pinning is simpler and safer** |
| Pagination | The dashboard tool returns `pageDetails`. Either loop internally and return the full list, or expose `pageNo` and describe `hasNextPage` so the model knows to continue |
| Tool descriptions | Rewrite anything saying "across all organizations" — that phrasing makes a model reach for the wrong tool |
| Error handling | Map `8083` and `8084` to an actionable message |

> `8083` means the header is missing — a retry will never fix it. An agent that
> sees a bare `8083` retries the identical request forever. Translate it in the
> tool's error path to something like *"This API needs an organization ID. Ask
> the user which organization to use."*

## Internal wikis, runbooks, onboarding guides

Nothing automated finds these. Budget an hour. Search for the eight paths, the
SDK method names in both casings, and the old operation titles ("Get Org List",
"Get All Dashboards", "Get Owned", "Get Shared"). The complete search list is in
`../../../05-knowledge-bases.md`, and `agent/scan.py` will find them in anything

**Onboarding guides are the worst case.** A new developer following "step 1: call
`GET /restapi/v2/orgs` to find your org ID" is stuck on their first morning.

## Deluge and no-code automations

Zoho Creator, Zoho Flow and CRM functions call the API through `invokeurl` with
hand-written headers — no compiler, no type check. Two changes per script: the
**URL**, and a **`headers` line** carrying `ZANALYTICS-ORGID`.

```javascript
orgId = "700000123456";
headersMap = Map();
headersMap.put("ZANALYTICS-ORGID", orgId);
response = invokeurl
[
  url :"https://analyticsapi.zoho.com/restapi/v2/orgs/workspaces"
  type :GET
  headers:headersMap
  connection:"analytics_oauth_connection"
];
```

Scripts already scoped to one workspace probably send the header already — check,
do not assume.

# The facts every part of this migration rests on

Condensed from `../../../../01-why-org-context.md` and `../../../../02-whats-changed.md`.
Read those for the full reasoning and worked examples.

## 1. The header is mandatory everywhere

`ZANALYTICS-ORGID` is now required on **every endpoint in the API**, not only the
ones this migration renames. Around 200 endpoints already required it; the change
is that the remaining handful no longer accept its absence.

Add it in the shared HTTP client or request builder, once. If `8083` appears on
every call at the same time, the shared builder is what was missed.

**Carry the ID as a string.** Organization IDs such as `700000123456` exceed
32-bit range, and in JavaScript leave safe-integer territory once concatenated
with other IDs. A silently truncated ID produces `8084` and looks like a typo.

## 2. The Organization ID comes from configuration

`GET /restapi/v2/orgs` was the discovery call. It is removed and **has no API
replacement** — deliberately. The point of the change is that an application
*states* its organization rather than discovering one.

Read it once from the Zoho Analytics UI → **Settings → Organisation**, and store
it next to the client ID and refresh token (`ZOHO_ANALYTICS_ORG_ID`).

Everything else the old endpoint returned is still available, organization-scoped:

| Old field | Where now |
|---|---|
| `orgId` | Configuration |
| `orgName`, `orgDesc` | UI → Settings → Organisation |
| `planName` | `GET /restapi/v2/subscription` (needs the header) |
| `numberOfWorkspaces` | Count `data.workspaces` from `GET /restapi/v2/orgs/workspaces` |
| `role` | `GET /restapi/v2/workspaces/{id}` with `CONFIG={"withUserRoleInfo":true}` |
| `isDefault` | No equivalent — the application decides now |

**Serving several organizations** changes from *discover then fan out* to
*configure then fan out*. Hold the list of organization IDs in configuration. If
the product must cover organizations that cannot be known in advance, add an
"Add organization" step to the setup flow and ask the user for the ID — the same
way you already ask for a client ID. Do not guess.

## 3. `8083` and `8084` are not retryable

| Code | Name | Means |
|---|---|---|
| `8083` | `ORGID_NOT_PRESENT_IN_THE_HEADER` | The header was missing or empty |
| `8084` | `ORGID_NOT_EXIST` | No organization has that ID |

Retrying the identical request fails identically. Anything with a retry policy —
an HTTP client, a job runner, an AI agent — must treat these as terminal and
surface an actionable message rather than looping.

## 4. The dashboard listing is paged

`GET /restapi/v2/orgs/dashboards` returns `data.views` **and** `data.pageDetails`,
where its three predecessors returned everything in one response.

Loop on `pageDetails.hasNextPage`. Never on page length — `hasNextPage` is
computed after duplicates and role-restricted entries have been removed from the
page, so a page can hold 3 entries when 100 were requested and still have more
behind it.

In the SDKs this is also a **return-type change**: an object where the old method
returned an array. In Python, Ruby, PHP, Node.js and Go that is a runtime failure,
not a compile error.

## What did not change

- **Authentication.** Same OAuth flow, same scopes. `ZohoAnalytics.metadata.read`
  covers all three new endpoints — the same scope the old ones used.
- **Data import and export.** Untouched.
- **`POST /restapi/v2/workspaces`** (Create Workspace). Shares a path with a
  removed `GET`; check the verb before rewriting that path.
- **Around 200 other endpoints** that were already organization-scoped.
- **The response envelope**, error-body shape, and CONFIG conventions.

## Why it was done

The old cross-organization endpoints had four problems, all consequences of not
naming an organization: the answer was ambiguous when a user belonged to several
organizations; responses mixed data from different organizations; nothing was
safe to cache; and the cost of the fan-out was invisible and unbounded.

Useful to explain when a user asks why there is no automatic redirect: the new
URLs and response shapes differ, so a redirect would break callers just as surely
as removal does — only silently.

# Timeline, and how to prove the migration is finished

Condensed from `../../../../06-timeline.md`.

## One date

**March 2027.** The eight replaced endpoints stop answering. No extension, no
opt-out, and no silent fallback — the new URLs and response shapes differ, so a
redirect would break callers just as surely as removal.

## Where things stand now

- **Both old and new endpoints answer.** Nothing is broken yet. This is the
  migration window.
- **The old endpoints are already out of the documentation** — the API reference,
  the OpenAPI specs, the OKF bundle, the Postman collection and all seven SDKs. A
  developer reading the docs today will not find them.
- **The SDKs are ahead of the server.** The methods are gone from all seven SDKs
  *now*, while the endpoints answer until 2027. Upgrading the SDK breaks the build
  before anything breaks in production. That is deliberate: it turns a 2027
  incident into a build-time problem.

## What "deprecated" actually means here

| Question | Answer |
|---|---|
| Returns correct data today? | Yes |
| Will get bug fixes? | No |
| Will get new fields when the new endpoints do? | No — they will drift apart |
| Appears in the documentation? | No, already removed |
| Still exposed by the SDKs? | No, removed from all seven today |
| Warning header on the response? | Do not rely on one — build your own monitoring |
| Will the date move? | Plan as though it will not |

Treat anything still calling them as already broken, just not yet failing.

## A sensible schedule

The window is long. Use a short slice of it early rather than a panicked slice
late — because the expensive part is not the code, it is the **discovery**: the
scheduled job nobody owns, the Deluge script in a Creator app, the notebook on an
analyst's laptop. Those surface slowly.

1. **Week 1 — measure exposure.** Run `agent/scan.py`, and add the monitoring
   alert. You cannot plan until you know how many call sites exist and who owns them.
2. **Week 2 — configure the Organization ID** and wire `ZANALYTICS-ORGID` into
   the shared request builder. One edit, most of the surface fixed.
3. **Weeks 3–4 — migrate the listings.** Do the two *changed* endpoints first
   (header only), then the listings, where response shapes change.
4. **Week 5 — refresh the contracts.** OpenAPI, Postman, OKF, MCP tool
   definitions, the wiki. Skipping this is how the old endpoints creep back in
   six months later.
5. **Then — watch the alert** until it is silent across a full billing cycle.

## The three completion checks

All three must pass. "We think we got them all" is not one of them.

**1. The code is clean.**

```bash
python3 agent/scan.py /path/to/project    # exits 0, no errors reported
```

A hit on `/restapi/v2/workspaces` is only a problem when the method is `GET`.

**2. The traffic is zero.** The monitoring alert on the eight deprecated paths
has not fired for a **full billing cycle** — month-end and quarter-end included.
Monthly and quarterly jobs are the ones everyone forgets. Do not close the ticket
on a quiet week.

**3. The contracts are fresh.**

```bash
grep '"version"' /path/to/okf/manifest.json | head -1       # expect 2.0.0

grep -rl "recentviews\|dashboards/owned\|dashboards/shared\|workspaces/owned\|workspaces/shared" \
  /path/to/openapi /path/to/postman /path/to/okf             # expect no output
```

## If you are reading this after March 2027

An integration has probably already broken. Smallest fix first:

1. Find the failing call — an explicit failure on one of the eight removed paths.
2. Get the Organization ID from **Settings → Organisation**.
3. Add the `ZANALYTICS-ORGID` header, re-point the path, and fix the response
   parsing. Use `zoho-analytics-v2-endpoint-migration`.

Dashboard listings need the most work: the replacement is paged and returns an
object rather than an array.

# Troubleshooting — symptom first

Condensed from `../../../../07-troubleshooting.md`, which has the full FAQ.
Every code as data, with fixes: `../../../migration-map.json` → `error_codes`.

## Start from the symptom

| Symptom | Most likely cause |
|---|---|
| `errorCode: 8083` | `ZANALYTICS-ORGID` was not sent |
| `errorCode: 8084` | The Organization ID is wrong, mistyped, or **silently truncated** |
| `errorCode: 7301` on a call that used to work | Not a member of the organization named in the header |
| `errorCode: 7103` on a workspace you know exists | Right workspace, wrong organization |
| `errorCode: 7104` on a view you know exists | Right view, wrong organization |
| `errorCode: 7476` | More than 100 workspaces in scope for the dashboard listing |
| `errorCode: 7387` | A `workspaceIds` entry is not in this organization |
| 404 / "no such endpoint" | Calling a removed path after March 2027 |
| Empty list, no error | **Correct** — nothing is visible to this caller |
| `KeyError: 'ownedWorkspaces'` | Response shape changed — merged into `data.workspaces` |
| `TypeError: list indices must be integers` | `getOrgDashboards` returns an object, not an array |
| Only ever 100 dashboards | Not paging — loop on `pageDetails.hasNextPage` |
| Dashboard list empty for everyone | Access Restrictions, or org-level listing switched off (`7430`/`7431`) |
| `NoMethodError` / `cannot find symbol` after SDK upgrade | The method moved off `AnalyticsClient` |

## The failure body

```json
{
  "status": "failure",
  "summary": "ORGID_NOT_PRESENT_IN_THE_HEADER",
  "data": { "errorCode": 8083, "errorMessage": "Organization id is not present in the header." }
}
```

**Branch on `data.errorCode`.** `summary` is the symbolic name; `errorMessage` is
human text and may be localised.

## Header and organization

| Code | Name | Fix |
|---|---|---|
| `8083` | `ORGID_NOT_PRESENT_IN_THE_HEADER` | Add the header. If this appears everywhere at once, the shared request builder was missed |
| `8084` | `ORGID_NOT_EXIST` | Re-read from Settings → Organisation. **Keep the ID a string** |
| `7301` | `SECURITY_NOT_PERMITTED` | The org exists but the user is not an active member. Also returned when Get Org Dashboards is called through a Client Portal / White Label domain |

> **`8084` is usually a type problem, not a typo.** IDs like `700000123456`
> exceed 32-bit range. Carry them as strings everywhere; a truncated ID produces
> `8084` and looks like a mistyped number.

## Not found *in this organization*

| Code | Name | Note |
|---|---|---|
| `7103` | — | Workspace not found in the organization you named |
| `7104` | `META_OBJECT_NOT_PRESENT` | View not found in the organization you named |

Both existed before, but their meaning **narrowed**: they used to mean "does not
exist anywhere", now "does not exist *here*". Check the header before doubting
the ID.

## Dashboard listing only

| Code | Name | Fix |
|---|---|---|
| `7387` | `DBID_NOT_BELONGS_TO_ZSOID` | A `workspaceIds` entry is foreign or missing. The **whole request** fails; bad IDs are not skipped. Build the list from Get Org Workspaces for the same org |
| `7430` | `ORG_LEVEL_VIEWS_NOT_ALLOWED` | Org-level listing switched off; you see this code as Account Admin. Use workspace-level APIs or contact support |
| `7431` | `ORG_LEVEL_VIEWS_NOT_ALLOWED_WL_USERS` | Same setting, reported to everyone else |
| `7476` | `ORG_LEVEL_VIEWS_WS_MORE_THAN_ALLOWED_LIMIT` | Omitted `workspaceIds` with more than 100 visible workspaces. Batch them |

## CONFIG validation

Rejected by the request filter before the handler runs — these describe the
request, not the data.

| Code | Name | Fix |
|---|---|---|
| `8507` | `MORE_THAN_MAX_LENGTH` | `searchKey` > 100 chars, `workspaceIds` > 10,000 chars, CONFIG > 11,000 chars |
| `8516` | `UNABLE_TO_PARSE_DATA_TYPE` | Send `{"pageNo": 2}`, not `{"pageNo": "2"}` |
| `8534` | `JSON_PARSE_ERROR` | Stringify then URL-encode. **Encode once, not twice** |
| `8539` | `INVALID_VALUE_NOT_ALLOWED` | A value is null/empty/blank — leave the key out instead |
| `8542` | `EXTRA_KEY_FOUND_IN_JSON` | Only `workspaceIds`, `pageNo`, `recordsPerPage`, `searchKey`. Check for typos like `pageNum` |
| `8544` | `OUT_OF_RANGE` | `pageNo` 1–1,000, `recordsPerPage` 1–500. `recordsPerPage: 1000` is a common mistake — the cap is 500 |
| `8547` | `ARRAY_SIZE_OUT_OF_RANGE` | Over 1,000 `workspaceIds`. Stay at or under 100 because of `7476` |

## Authentication

`8535` `INVALID_OAUTHTOKEN` — refresh the token. All three new endpoints need
`ZohoAnalytics.metadata.read`, the same scope the old ones used, **so this is not
caused by the migration**. No new OAuth scopes are required.

## Answers people ask for first

- **Can I keep using the old endpoints until 2027?** They answer, but get no
  fixes and no new fields. Anything still calling them is already unsupported.
- **Why no automatic redirect?** The URLs and response shapes differ. A redirect
  would break callers silently instead of loudly.
- **Where do I get the Organization ID?** UI → **Settings → Organisation**. There
  is no API for it.
- **My app serves users across several organizations.** Configure the list of
  organization IDs and fan out explicitly, one `OrgAPI` per organization.
- **Why only 100 dashboards?** That is one page. Loop on `hasNextPage`.
- **How do I tell owned from shared now?** Derive it client-side by comparing
  `createdBy` to the caller — and check whether the split is still wanted.
- **Did `isDefault` change?** On a workspace it means the *caller's* default.
- **Do I need new OAuth scopes?** No.
- **Does this affect import or export?** No.
- **Is `POST /restapi/v2/workspaces` affected?** No. Create Workspace is untouched.
- **Our AI assistant keeps suggesting the old endpoints.** Its index still holds
  the deleted documents. Drop the vector index and rebuild from the 2.0.0 bundle —
  see `zoho-analytics-v2-artifact-migration`.

"""Find Zoho Analytics v2 code that still uses the removed cross-organization API.

Every pattern comes from migration-map.json — this script holds no facts of its own.

    python3 scan.py /path/to/your/project          report every hit
    python3 scan.py /path/to/your/project --json   machine-readable, for an agent
    python3 scan.py --self-check                   verify the map against the chapters

Exits 1 when anything of severity "error" is found, so it works as a CI gate.
No third-party dependencies — standard library only, same as build.py.
"""

import json
import re
import sys
from pathlib import Path

HERE = Path(__file__).resolve().parent
MAP_FILE = HERE / "migration-map.json"
CHAPTERS = HERE.parent

SKIP_DIRS = {
    ".git", ".hg", ".svn", "node_modules", "vendor", "venv", ".venv", "env",
    "__pycache__", ".mypy_cache", ".pytest_cache", ".tox", ".gradle", ".idea",
    ".vscode", "dist", "build", "target", "out", "bin", "obj", "coverage",
    ".next", ".nuxt", ".terraform", "site-packages",
}

# endpoint can hide in, including the artefacts chapter 05 lists.
SCAN_SUFFIXES = {
    ".java", ".py", ".cs", ".go", ".php", ".js", ".jsx", ".ts", ".tsx", ".rb",
    ".kt", ".scala", ".swift", ".c", ".cpp", ".h", ".rs", ".dg", ".ds",
    ".json", ".yaml", ".yml", ".toml", ".xml", ".properties", ".env",
    ".md", ".mdx", ".rst", ".txt", ".adoc", ".html", ".htm",
    ".sh", ".bash", ".zsh", ".ps1", ".sql", ".tf", ".gradle",
}

COLOR = sys.stdout.isatty()


def paint(text: str, code: str) -> str:
    return f"\033[{code}m{text}\033[0m" if COLOR else text


def load_map() -> dict:
    try:
        return json.loads(MAP_FILE.read_text(encoding="utf-8"))
    except FileNotFoundError:
        sys.exit(f"error: {MAP_FILE} not found")
    except json.JSONDecodeError as exc:
        sys.exit(f"error: {MAP_FILE} is not valid JSON — {exc}")


def compile_patterns(data: dict) -> list[dict]:
    out = []
    for p in data["scan_patterns"]["patterns"]:
        try:
            p = dict(p, compiled=re.compile(p["regex"]))
        except re.error as exc:
            sys.exit(f"error: pattern {p['id']} has an invalid regex — {exc}")
        out.append(p)
    return out


def walk(root: Path):
    if root.is_file():
        yield root
        return
    for path in sorted(root.rglob("*")):
        if not path.is_file():
            continue
        if any(part in SKIP_DIRS for part in path.parts):
            continue
        if path.suffix.lower() not in SCAN_SUFFIXES:
            continue
        try:
            if path.stat().st_size > MAX_BYTES:
                continue
        except OSError:
            continue
        yield path


def scan(root: Path, patterns: list[dict]) -> list[dict]:
    findings = []
    for path in walk(root):
        try:
            text = path.read_text(encoding="utf-8", errors="ignore")
        except OSError:
            continue
        # Cheap reject: nothing in the map can match a file with no mention
        # of the API surface at all.
        if "restapi/v2" not in text and "Workspaces" not in text \
                and "workspaces" not in text and "ashboard" not in text \
                and "ecent" not in text and "Orgs" not in text and "orgs" not in text:
            continue
        lines = text.splitlines()
        for number, line in enumerate(lines, start=1):
            if len(line) > 2000:
                line = line[:2000]
            for pattern in patterns:
                if pattern["compiled"].search(line):
                    findings.append({
                        "file": str(path),
                        "line": number,
                        "text": line.strip()[:200],
                        "pattern": pattern["id"],
                        "severity": pattern["severity"],
                        "message": pattern["message"],
                        "chapter": pattern["chapter"],
                    })
    return findings


def report(findings: list[dict], root: Path, data: dict) -> None:
    deadline = data["deadline"]["removal"]
    if not findings:
        print(paint("✓ No deprecated Zoho Analytics v2 usage found.", "32"))
        print(f"  Scanned: {root}")
        return

    errors = [f for f in findings if f["severity"] == "error"]
    warns = [f for f in findings if f["severity"] != "error"]

    by_pattern: dict[str, list[dict]] = {}
    for f in findings:
        by_pattern.setdefault(f["pattern"], []).append(f)

    print(f"Scanned: {root}")
    print(f"Found {len(findings)} occurrence(s) across {len(by_pattern)} issue type(s).")
    print(f"The removed endpoints stop answering in {paint(deadline, '1;33')}.\n")

    for pattern_id, group in by_pattern.items():
        severity = group[0]["severity"]
        tag = paint("ERROR", "1;31") if severity == "error" else paint("WARN ", "1;33")
        print(f"{tag} {paint(pattern_id, '1')}  ({len(group)} occurrence(s))")
        print(f"      {group[0]['message']}")
        print(f"      → {group[0]['chapter']}")
        for f in group[:20]:
            print(f"        {f['file']}:{f['line']}  {f['text']}")
        if len(group) > 20:
            print(f"        … and {len(group) - 20} more")
        print()

    print(f"{len(errors)} error(s), {len(warns)} warning(s).")
    if warns:
        print("Warnings are usually fine if the call is already on an OrgAPI or "
              "WorkspaceAPI instance — check each one.")


def self_check(data: dict) -> int:
    """Verify the map still agrees with the chapters it was derived from.

    This is the drift guard. The chapters are the source of truth; if the map
    claims an endpoint or method the prose has never heard of, the map is stale.
    """
    problems: list[str] = []

    chapter_text: dict[str, str] = {}
    for key, meta in data["chapters"].items():
        path = CHAPTERS / meta["file"]
        if not path.exists():
            problems.append(f"chapter {key}: {meta['file']} does not exist")
            continue
        chapter_text[key] = path.read_text(encoding="utf-8")

    everything = "\n".join(chapter_text.values())

    # 1. The deadline must match build.py's single constant.
    build_py = CHAPTERS / "build.py"
    if build_py.exists():
        match = re.search(r'REMOVAL_DEADLINE\s*=\s*"([^"]+)"', build_py.read_text(encoding="utf-8"))
        if not match:
            problems.append("build.py: REMOVAL_DEADLINE not found")
        elif match.group(1) != data["deadline"]["removal"]:
            problems.append(
                f"deadline drift: map says {data['deadline']['removal']!r}, "
                f"build.py says {match.group(1)!r}"
            )
    else:
        problems.append("build.py not found — cannot verify the deadline")

    # 2. Every old and new endpoint path in the map must appear in the prose.
    for entry in data["endpoints"]["replaced"]:
        old_path = entry["old"].split(" ", 1)[1]
        if old_path not in everything:
            problems.append(f"endpoint {old_path} is in the map but in no chapter")
        if entry["new"]:
            new_path = entry["new"].split(" ", 1)[1]
            if new_path not in everything:
                problems.append(f"replacement {new_path} is in the map but in no chapter")

    for entry in data["endpoints"]["new"]:
        if entry["path"] not in everything:
            problems.append(f"new endpoint {entry['path']} is in the map but in no chapter")

    # 3. Every SDK method name in the map must appear in chapter 04.
    sdk_text = chapter_text.get("04", "")
    for entry in data["sdk"]["method_map"]:
        if entry["old"] not in sdk_text:
            problems.append(f"SDK method {entry['old']} is in the map but not in chapter 04")
        if entry.get("new") and entry["new"] not in sdk_text:
            problems.append(f"SDK method {entry['new']} is in the map but not in chapter 04")

    # 4. Every error code in the map must appear somewhere in the prose.
    for entry in data["error_codes"]:
        if str(entry["code"]) not in everything:
            problems.append(f"error code {entry['code']} is in the map but in no chapter")

    # 5. Every chapter anchor the patterns point at must resolve.
    for pattern in data["scan_patterns"]["patterns"]:
        target = pattern["chapter"]
        file_part, _, anchor = target.partition("#")
        path = CHAPTERS / file_part
        if not path.exists():
            problems.append(f"pattern {pattern['id']}: {file_part} does not exist")
            continue
        if anchor:
            body = path.read_text(encoding="utf-8")
            slugs = {slugify(h) for h in re.findall(r"^#{2,4}\s+(.+)$", body, re.M)}
            if anchor not in slugs:
                problems.append(f"pattern {pattern['id']}: #{anchor} does not resolve in {file_part}")

    # 6. The patterns must actually fire on the chapters' own "Before" examples.
    for pattern in data["scan_patterns"]["patterns"]:
        if not re.compile(pattern["regex"]).search(everything):
            problems.append(f"pattern {pattern['id']} matches nothing in the guide — probably dead")

    if problems:
        print(paint(f"✗ {len(problems)} problem(s):", "1;31"))
        for problem in problems:
            print(f"  - {problem}")
        return 1

    counts = (
        f"{len(data['endpoints']['replaced'])} replaced endpoints, "
        f"{len(data['sdk']['method_map'])} SDK methods, "
        f"{len(data['error_codes'])} error codes, "
        f"{len(data['scan_patterns']['patterns'])} scan patterns"
    )
    print(paint("✓ migration-map.json agrees with the chapters.", "32"))
    print(f"  {counts}")
    return 0


def slugify(heading: str) -> str:
    """Mirror build.py: strip a leading section number, then slug the rest."""
    heading = re.sub(r"^\d+\.\s*", "", heading.strip())
    heading = re.sub(r"`([^`]*)`", r"\1", heading)
    heading = re.sub(r"<[^>]+>", "", heading)
    heading = heading.replace("&mdash;", "").replace("—", "")
    heading = re.sub(r"[^\w\s-]", "", heading.lower())
    return re.sub(r"[-\s]+", "-", heading).strip("-")

# Zoho Analytics REST API v2 — mandatory organization context

Instructions for AI coding agents working on code that calls the Zoho Analytics
REST API v2. Written for tools that read `AGENTS.md` (Cursor, GitHub Copilot,
Codex, Zed, Jules and others). Agents that support Agent Skills should load
`skills/zoho-analytics-v2-org-context/` instead — it carries the same facts with
task-specific detail.

## What changed

Every call must now name its organization. Eight cross-organization endpoints
were replaced by three organization-scoped ones; two more kept their URL but now
require the `ZANALYTICS-ORGID` header.

**The eight removed endpoints stop answering in March 2027.**

| Old | New |
|---|---|
| `GET /restapi/v2/orgs` | **No endpoint** — the Org ID goes in configuration |
| `GET /restapi/v2/workspaces` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/workspaces/owned` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/workspaces/shared` | `GET /restapi/v2/orgs/workspaces` |
| `GET /restapi/v2/dashboards` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/dashboards/owned` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/dashboards/shared` | `GET /restapi/v2/orgs/dashboards` |
| `GET /restapi/v2/recentviews` | `GET /restapi/v2/orgs/recentitems` |

SDK methods moved off `AnalyticsClient`: `getWorkspaces` → `OrgAPI.getOrgWorkspaces`,
`getDashboards` → `OrgAPI.getOrgDashboards`, `getRecentViews` → `OrgAPI.getOrgRecentItems`,
`getWorkspaceDetails` → `WorkspaceAPI`, `getViewDetails` → `OrgAPI`, `getOrgs` → removed.

## Rules

1. **Never write a deprecated endpoint or SDK method**, even as an interim step.
   There is no fallback and no redirect.
2. **Send `ZANALYTICS-ORGID` on every request.** Add it to the shared HTTP client
   or request builder, not per call site.
3. **The Organization ID comes from configuration** (`ZOHO_ANALYTICS_ORG_ID`),
   read once from the Zoho Analytics UI → Settings → Organisation. There is no
   API that returns it. Never invent, guess or hardcode one.
4. **Carry the Organization ID as a string.** These numbers exceed 32-bit range;
   a truncated ID produces error `8084` and looks like a typo.
5. **Check the HTTP verb before rewriting `/restapi/v2/workspaces`.** `POST` on
   that path is Create Workspace and is unaffected.
6. **`GET /restapi/v2/orgs/dashboards` is paged.** Loop on
   `pageDetails.hasNextPage` — never on page length. It returns an object with
   `views` and `pageDetails`, where the old endpoints returned a plain array.
7. **`8083` and `8084` are terminal.** The header is missing / the ID is unknown.
   Never retry; surface an actionable message.
8. **Merged response keys:** `ownedWorkspaces` + `sharedWorkspaces` →
   `data.workspaces`; `ownedViews` + `sharedViews` → `data.views`.

# analytics-api skills

Six skills that together regenerate **every knowledge base in this repository from the markdown
reference in `<VERSION>/md/`**. The markdown is the source of truth; nothing else is.

| Skill | Knowledge base it produces | Directory | Produced by |
|---|---|---|---|
| [`analytics-api-generate`](analytics-api-generate/SKILL.md) | *(router / full pipeline)* | — | `tools/api-agent/pipeline.py` |
| [`analytics-zenesis-oas`](analytics-zenesis-oas/SKILL.md) | OpenAPI 3.1 + `x-zenesis-*` specifications | `<V>/zenesis-oas/` | authored by an agent from `md/` |
| [`analytics-oas-samples`](analytics-oas-samples/SKILL.md) | SDK snippets in 9 languages | `<V>/zenesis-oas-samples/` | authored by an agent from `md/` |
| [`analytics-oas`](analytics-oas/SKILL.md) | vendor-neutral OpenAPI 3.1 | `<V>/oas/` | `make -C tools/zenesis-oas to-analytics` |
| [`analytics-okf`](analytics-okf/SKILL.md) | Open Knowledge Format v0.2 bundle | `<V>/okf/` | `tools/okf/build_okf.py` |
| [`analytics-postman`](analytics-postman/SKILL.md) | Postman collection + environment | `<V>/postman/` | `tools/postman/build_postman.py` |

**Start at [`analytics-api-generate`](analytics-api-generate/SKILL.md)** unless you already know
which knowledge base you are working on.

## The two kinds of generation

They are not the same job, and confusing them is the most common mistake:

- **`zenesis-oas/` and `zenesis-oas-samples/` are *authored*.** No script derives them from the
  markdown. An agent (or a human) reads the markdown section and writes the operation and the nine
  snippets, following a fixed contract. The repository calls these "sources" because the downstream
  tools read them, but relative to `md/` they are *generated by you*. Their skills are therefore
  **authoring contracts**: what each markdown element becomes, character for character.
- **`oas/`, `okf/` and `postman/` are *built*.** A deterministic script deletes and rewrites them.
  Their skills are **operating manuals**: what the script reads, what it emits, what each warning
  means, and what to fix in the sources — never in the output.

## Dependency order

```
  <V>/manifest.json  ──────────────────────────── the spine: domains, groups, tags, slugs
          │
  <V>/md/ ──► analytics-zenesis-oas ──► <V>/zenesis-oas/ ─┬─► analytics-oas      ──► <V>/oas/ ─┐
          └─► analytics-oas-samples ──► <V>/zenesis-oas-samples/ ─┐                            │
                                                                  ├─► analytics-okf ──► <V>/okf/
                                                                  │                        │
                                                                  └────────────────────────┴─► analytics-postman ──► <V>/postman/
```

Postman needs OKF *and* OAS; OKF needs the specs *and* the samples *and* the markdown. Never build
out of order — `tools/api-agent/pipeline.py` enforces it.

## Conventions every skill assumes

- `<VERSION>` is a `vN.N` directory (`v2.0` today). `manifest.json` at the repository root names
  every version and which is `latest`. A change belongs to exactly one version.
- **Titles join the knowledge bases.** The markdown heading `## N. Title` must equal the operation's
  `x-zenesis-title` character for character.
- **Generated directories are never hand-edited**: `oas/` (except `oas/common/`), `okf/`, `postman/`.
- Standard library Python 3.8+ and `make`. Nothing to install, nothing is pushed anywhere.

02Error codes

Every code this change can produce. The failure body always looks like this:

{
  "status": "failure",
  "summary": "ORGID_NOT_PRESENT_IN_THE_HEADER",
  "data": {
    "errorCode": 8083,
    "errorMessage": "Organization id is not present in the header."
  }
}

Branch on data.errorCode. summary is the symbolic name; errorMessage is human text and may be localised.

Header and organization

CodeNameIn plain wordsFix
8083ORGID_NOT_PRESENT_IN_THE_HEADERYou did not send ZANALYTICS-ORGID, or sent it empty.Add the header. If this appears everywhere at once, you missed the shared request builder.
8084ORGID_NOT_EXISTNo organization has that ID. Usually a typo, a truncated number, or an ID from a different data centre.Re-read it from Settings → Organisation. Keep it a string — these numbers overflow a 32-bit integer.
7301SECURITY_NOT_PERMITTEDThe organization exists, but the authenticated user is not an active member of it. Also returned when Get Org Dashboards is called through a Client Portal / White Label domain.Check that the token and the organization belong together. For Client Portal, use the standard API host.
8084 is often a type problem, not a typo

Organization IDs such as 700000123456 exceed 32-bit range. In JavaScript they also exceed Number.MAX_SAFE_INTEGER territory once concatenated with other IDs. Carry them as strings everywhere. A silently truncated ID produces 8084 and looks like a typo.

Target not found in this organization

CodeNameIn plain wordsFix
7103—The workspace was not found in the organization you named.The workspace probably lives in a different organization. Check the header before you doubt the ID.
7104META_OBJECT_NOT_PRESENTThe view was not found in the organization you named.Same — check the header first.

These two codes existed before, but their meaning narrowed: they used to mean "does not exist anywhere", and now mean "does not exist here".

Dashboard listing only

CodeNameIn plain wordsFix
7387DBID_NOT_BELONGS_TO_ZSOIDOne of the workspaceIds you sent belongs to another organization, or does not exist. The whole request fails; bad IDs are not skipped.Build the list from Get Org Workspaces for the same organization.
7430ORG_LEVEL_VIEWS_NOT_ALLOWEDOrg-level view listing is switched off for this organization. You see this code because you are the Account Admin.Use the workspace-level view APIs, or contact support to enable it.

7476ORG_LEVEL_VIEWS_WS_MORE_THAN_ALLOWED_LIMITYou omitted workspaceIds and the caller can see more than 100 workspaces.Send workspaceIds in batches of 100. See the recipe.

CONFIG validation

These are rejected by the request filter before the handler runs, so they tell you about the request, not about your data.

CodeNameIn plain wordsFix
8507MORE_THAN_MAX_LENGTHsearchKey over 100 characters, workspaceIds over 10,000 characters, or CONFIG over 11,000 characters.Shorten it, or send fewer workspace IDs per call.
8516UNABLE_TO_PARSE_DATA_TYPEpageNo or recordsPerPage arrived as a string, not a number.Send {"pageNo": 2}, not {"pageNo": "2"}.
8534JSON_PARSE_ERRORCONFIG is not valid JSON, or workspaceIds is not an array.Stringify the JSON, then URL-encode it. Encode once, not twice.
8539INVALID_VALUE_NOT_ALLOWEDA CONFIG value is null, empty or blank — including a single blank workspaceIds entry.Leave the key out rather than sending an empty value.
8542EXTRA_KEY_FOUND_IN_JSONCONFIG has a key other than workspaceIds, pageNo, recordsPerPage, searchKey.Remove it. Check for typos such as pageNum.
8544OUT_OF_RANGEpageNo outside 1–1,000, or recordsPerPage outside 1–500.Clamp before sending. recordsPerPage: 1000 is a common mistake — the cap is 500.
8547ARRAY_SIZE_OUT_OF_RANGEMore than 1,000 entries in workspaceIds.Batch. In practice stay at or under 100 because of 7476.

03Frequently asked questions

Q. Can I just keep sending the old endpoints until 2027?

They will answer until then, so technically yes — and if you stay on SDK 2.9.0 or below, the methods are still there to call. But they get no fixes, no new fields and no support, and SDK 2.10.0 onwards does not expose them, so you are also pinned to an old client. Anything you ship today against a deprecated endpoint is work you have committed to redoing before March 2027.

Q. Why was there no automatic redirect from the old URL to the new one?

Because a redirect would be a lie. GET /restapi/v2/workspaces returned ownedWorkspaces and sharedWorkspaces across every organization; GET /restapi/v2/orgs/workspaces returns workspaces for one. A client following a redirect would get a 200 with a body it cannot parse — a harder failure to diagnose than a clear error.

Q. Where do I get the Organization ID now?

Zoho Analytics → Settings → Organisation. Copy it once into configuration. See chapter 01.

Q. My application serves users across several organizations. What now?

Keep a list of Organization IDs in your own configuration or database and loop over it, sending a different ZANALYTICS-ORGID per iteration. The fan-out recipe has working code. If you cannot know the organizations in advance, add an "Add organization" step to your setup flow and ask the user for the ID.

Q. Why do I only get 100 dashboards?

recordsPerPage defaults to 100 and the endpoint is paged. Loop while data.pageDetails.hasNextPage is true. Do not stop because a page came back short — hasNextPage is computed after filtering, so a short page can still have more behind it. Paging code.

Q. How do I tell owned dashboards from shared ones now?

sharedBy on each entry holds the email address of whoever shared it with you; it is empty or absent for things you own. Same for workspaces, using createdBy. The information moved from the URL into the row.

Q. isDefault used to mean the organization's default workspace. Did that change?

The old reference said that, and it was wrong. isDefault has always been per user — it is true for the calling user's own default workspace. The new reference states this explicitly. Do not cache it as a property of the workspace; two users see different values for the same row.

Q. Can I still get a list of every organization I belong to?

Not from the API. That capability was the thing being removed: the API no longer discovers organizations for you, it acts on the one you name. Read the ID from the UI and configure it.

Q. Do I need new OAuth scopes?

No. All three replacements use ZohoAnalytics.metadata.read, exactly like the endpoints they replace. Existing tokens work unchanged.

Q. Does this affect data import or export?

No. Import, export, row operations, schema operations and everything else under /workspaces/{workspace-id}/… already required the header and are untouched.

Q. Is POST /restapi/v2/workspaces affected?

No. Only the GET on that path was removed. Create Workspace is unchanged. Check the method before acting on a grep hit.

Q. Why did getViewDetails move to OrgAPI rather than ViewAPI?

A ViewAPI instance is constructed from an organization and a workspace and a view. The Get View Details endpoint has no workspace in its URL — it resolves the view from the organization alone. OrgAPI carries exactly an organization, so it is the honest home. Putting it on ViewAPI would force you to supply a workspace ID the endpoint never uses.

Q. Why did getWorkspaceDetails lose its workspaceId argument?

Because WorkspaceAPI already holds it: you passed it to getWorkspaceInstance(orgId, workspaceId). Passing it again would let the two disagree. The method gained an optional config argument instead, for withUserRoleInfo.

Q. What happens to recent items I viewed in my other organizations?

They are still there, in those organizations. Call GET /restapi/v2/orgs/recentitems once per organization with the matching header. The list is capped at 20 entries per organization.

Q. The new recent-items list points at a view I cannot open. Bug?

No — documented behaviour. Recent items are filtered by workspace visibility only, with no view-level check. Treat viewId as a hint and handle a refusal when you open it.

Q. Our AI assistant keeps suggesting the old endpoints.

Its knowledge index still contains the deleted documents. An incremental re-index adds the new ones but does not remove the old. Drop the index and rebuild it from OKF bundle 2.0.0. See chapter 05.

Q. How do I know when I am finished?

Three things, all true at once: the grep is clean, the monitoring alert on the deprecated paths has been silent for a full billing cycle, and every contract copy (OpenAPI, Postman, OKF, MCP) has been refreshed. The full check.

04Still stuck

  1. Re-read the endpoint section for the specific call. The field mapping tables catch most parsing failures.
  2. Reproduce the call with curl, with the header written out by hand. That separates "my code is wrong" from "my request is wrong".
curl -s "https://analyticsapi.zoho.com/restapi/v2/orgs/workspaces" \
  -H 'ZANALYTICS-ORGID: 700000123456' \
  -H 'Authorization: Zoho-oauthtoken 1000.xxxxxx.yyyyyy'
  1. If that works and your code does not, the difference is in your client — usually a missing header, a double-encoded CONFIG, or an Organization ID that became a number somewhere.
Deprecated

A last reminder: the eight endpoints this guide replaces are deprecated and stop answering in March 2027. If you are reading this page because something broke, check the timeline first — the fix may simply be that the endpoint no longer exists.
